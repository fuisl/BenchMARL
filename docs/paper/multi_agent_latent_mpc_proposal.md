# Counterfactual Joint-Action Prediction for Multi-Agent Latent MPC

## Overview

Can a **simple latent world model** plan well for multiple cooperative agents when MPC evaluates **joint action combinations that were not observed together during training**?

The goal is deliberately small:

> **Show that explicitly modelling how agents affect one another improves counterfactual plan ranking and closed-loop multi-agent control.**

## Motivation

Single-agent latent planning is conceptually simple:

```math
z_{t+1} = f(z_t, a_t)
```

The model predicts what happens after one action, and MPC searches over possible future action sequences.

For multiple agents, the transition becomes:

```math
z_{t+1}^{i}
=
f_i
\left(
z_t^i,
a_t^i,
\{z_t^j,a_t^j\}_{j\neq i}
\right)
```

Now agent $i$'s future depends not only on its own action, but also on the states and actions of the other agents.

This creates the core multi-agent difficulty:

> **Actions have cross-agent consequences.**

The planner must therefore answer questions such as:

- What happens if agent 1 changes its action?
- What happens if agent 2 changes its action at the same time?
- What happens if several agents choose a combination of actions that was rare or absent in the training data?

That is the part we want to study.

## Related Work

We should not claim that multi-agent world models or multi-agent planning are new.

Existing work already includes:

- **MAMBA** — Dreamer-style multi-agent world models with communication.
- **MBVD** — imagined latent futures used for cooperative value decomposition.
- **MABL** — local and global latent variables for multi-agent world modelling.
- **MAZero** — explicit planning in learned latent dynamics using MCTS.
- **CoDreamer** — Dreamer-style world models with GNN-based interaction.
- **MARIE** — local temporal modelling with centralized cross-agent aggregation.

So the paper is **not**:

> “We introduce world models to MARL.”

It is also **not**:

> “We introduce planning to MARL.”

The contribution has to be more specific.

## Research Gap

World models are normally trained on trajectories generated by some behaviour policy.

An offline dataset looks like:

```math
\mathcal D
=
\{
(Z_t,A_t,Z_{t+1})
\}
```

with joint action

```math
A_t =
(a_t^1,a_t^2,\ldots,a_t^N).
```

During training, the model sees particular combinations of actions that occurred together.

For example, a cooperative behaviour policy might often produce:

```math
(a^1=\text{left},\ a^2=\text{right}).
```

The model may become very good at predicting what happens after this observed combination.

But MPC does something different.

It deliberately evaluates alternatives such as:

```math
(\text{left},\text{left}),
\qquad
(\text{right},\text{left}),
\qquad
(\text{right},\text{right}).
```

Some of these joint action combinations may be uncommon or completely unseen in the training trajectories.

Therefore:

```math
\boxed{
\text{low prediction error on logged trajectories}
\not\Rightarrow
\text{reliable counterfactual joint-action prediction}
}
```

This is the gap we want to study.

### Concise Gap Statement

> **Existing multi-agent world models capture inter-agent dependencies, but it remains unclear whether simple latent predictive models can faithfully evaluate the counterfactual joint actions generated by MPC. A model may predict observed trajectories well while still ranking unseen coordinated actions incorrectly.**

### Why Prediction Error Alone Is Insufficient

A world model is useful for MPC only if it helps the planner choose the right action sequence.

Suppose two candidate plans are $A_1$ and $A_2$.

If the real environment says

```math
J(A_1) < J(A_2),
```

then ideally the world model should also predict

```math
\hat J(A_1) < \hat J(A_2).
```

The important question is therefore not only:

> “Does the model predict the next latent state accurately?”

but:

> **“Does the model rank candidate joint-action plans correctly?”**

A model could have:

```math
\text{low one-step MSE}
```

but still have:

```math
\text{poor plan ranking}.
```

For planning, the second failure is much more serious.

## Hypothesis and Research Questions

The central hypothesis is:

> **Explicitly modelling cross-agent state-action interactions should improve counterfactual joint-action prediction, which should improve plan ranking, and therefore improve closed-loop latent MPC.**

The expected causal chain is:

```math
\boxed{
\text{interaction modelling}
\rightarrow
\text{better counterfactual prediction}
\rightarrow
\text{better plan ranking}
\rightarrow
\text{better control}
}
```

This is the entire paper story.

### Primary Research Question

```math
\boxed{
\textbf{Does interaction-aware joint-action prediction improve}
}
```

```math
\boxed{
\textbf{plan ranking and closed-loop control in cooperative multi-agent MPC?}
}
```

### Secondary Research Question

```math
\boxed{
\textbf{Does the benefit increase as interactions between agents become stronger?}
}
```

Keep the paper to one main RQ, with the second only as supporting analysis.

## Proposed Method

The method should stay close to the simplicity of LeWM.

### Per-Agent Latent Representation

Each agent observation is encoded as:

```math
z_t^i = E(o_t^i).
```

Initially, use **vector observations from VMAS** rather than pixels.

The encoder can therefore be a small MLP.

No foundation model is needed for the first paper.

### Interaction-Aware Predictor

For each agent, aggregate information from the other agents:

```math
m_i
=
\sum_{j\neq i}
\phi
\left(
z_t^i,
z_t^j,
a_t^i,
a_t^j
\right).
```

Then predict:

```math
\hat z_{t+1}^{i}
=
f
\left(
z_t^i,
a_t^i,
m_i
\right).
```

The key architectural difference is that the transition of agent $i$ explicitly depends on the state-action pairs of other agents.

A small GNN/message-passing block is enough.

The point is **not** to propose a complicated architecture.

The point is to test whether explicit interaction structure matters for planning.

### Training Objective

Keep the objective minimal.

A LeWM-style version is:

```math
\mathcal L
=
\mathcal L_{\text{latent prediction}}
+
\lambda
\mathcal L_{\text{anti-collapse}}.
```

For example:

```math
\mathcal L_{\text{pred}}
=
\frac{1}{N}
\sum_i
\left\|
\hat z_{t+1}^i
-
z_{t+1}^i
\right\|_2^2.
```

Use the same anti-collapse mechanism for all compared models.

The anti-collapse method itself should **not** be the contribution.

No need initially for:

- reward prediction,
- value prediction,
- reconstruction decoder,
- KL terms,
- uncertainty model,
- inverse dynamics,
- communication loss,
- role-specific loss,
- foundation initialization.

The experiment should isolate **interaction modelling**.

### Centralized CEM-MPC

Use centralized CEM-MPC.

At state $Z_t$, the planner samples candidate joint action sequences:

```math
A_{t:t+H-1}
=
\{
A_t,A_{t+1},\ldots,A_{t+H-1}
\},
```

where

```math
A_t =
(a_t^1,\ldots,a_t^N).
```

The world model rolls each candidate forward:

```math
Z_t
\rightarrow
\hat Z_{t+1}
\rightarrow
\cdots
\rightarrow
\hat Z_{t+H}.
```

The planner chooses:

```math
A^*
=
\arg\min_A
C(\hat Z_{t+H},Z_g)
```

or maximizes the known task objective if the environment provides one.

Execute only the first joint action, observe the real next state, and replan.

For the first paper, centralized planning is acceptable.

We are **not** solving decentralized execution yet.

## Experimental Design

### Environment and Tasks

Use **VMAS**.

Reasons:

- simple vector states,
- continuous control,
- naturally multi-agent,
- fast simulation,
- easy counterfactual rollout in the true simulator,
- suitable for a single-GPU experiment.

Start with:

```math
N \in \{2,3,4\}.
```

Use only 2–3 tasks.

Prefer tasks with different levels of interaction:

1. **Weak interaction** — agents can mostly solve their parts independently.
2. **Moderate interaction** — coordination helps.
3. **Strong interaction** — agents directly affect each other's ability to succeed.

This lets us test whether relational modelling matters specifically when interaction matters.

### Models to Compare

Keep the comparison small.

| Model | Transition | Purpose |
|---|---|---|
| **Independent latent model** | $\hat z_{t+1}^{i}=f(z_t^i,a_t^i)$ | Tests a model in which each agent ignores every other agent's state and action. |
| **Central concatenated model** | $\hat Z_{t+1}=f(Z_t,A_t)$ | Tests whether access to global information alone is sufficient. |
| **Relational multi-agent latent model** | $\hat z_{t+1}^{i}=f(z_t^i,a_t^i,m_i)$ | Tests explicit cross-agent effects through message passing; this is the proposed model. |

Use the same data, latent size, loss, and CEM planner for all three models.

## Evaluation

### Standard Prediction Accuracy

Measure:

```math
\text{one-step prediction MSE}.
```

Also optionally:

```math
k\text{-step rollout error},
\qquad
k\in\{1,3,5,10\}.
```

This is useful but not the main result.

### Counterfactual Prediction

Take a real state $Z_t$.

Generate many alternative joint actions:

```math
A_t^{(1)},A_t^{(2)},\ldots,A_t^{(K)}.
```

For every candidate:

1. predict the next state using the learned world model;
2. execute the same joint action once in the real VMAS simulator;
3. compare the two outcomes.

This directly measures whether the world model understands alternative joint actions rather than only the actions seen in the logged trajectory.

### Plan-Ranking Accuracy

For candidate plans

```math
A^{(1)},\ldots,A^{(K)},
```

calculate predicted cost:

```math
\hat J(A^{(k)})
```

and true simulator cost:

```math
J(A^{(k)}).
```

Then calculate rank correlation:

```math
\rho_{\text{plan}}
=
\operatorname{Spearman}
\left(
\hat J(A^{(k)}),
J(A^{(k)})
\right).
```

This directly tests:

> **Does the learned world model know which plan is better?**

This should be one of the headline metrics.

### Closed-Loop MPC Control

Finally compare actual control:

- success rate,
- episode return,
- final goal distance,
- collisions or constraint violations where relevant.

The important link is:

```math
\text{counterfactual accuracy}
\rightarrow
\text{plan ranking}
\rightarrow
\text{closed-loop control}.
```

## Expected Result

The nicest possible result would be something like:

```math
\text{Independent WM}
\approx
\text{Relational WM}
```

in ordinary one-step prediction error,

but:

```math
\rho_{\text{plan}}^{\text{Relational}}
>
\rho_{\text{plan}}^{\text{Independent}}
```

and:

```math
J_{\text{MPC}}^{\text{Relational}}
>
J_{\text{MPC}}^{\text{Independent}}.
```

That would demonstrate something scientifically interesting:

> **Standard world-model prediction metrics can hide errors that matter specifically for multi-agent planning.**

The relational representation would matter not because it gives dramatically better generic prediction, but because it gives **more faithful counterfactual predictions for control**.

## Limitation: Architecture Cannot Create Missing Information

A relational model cannot magically infer causal effects if the training data contains no useful variation.

Suppose agents always execute exactly the same coordinated behaviour:

```math
(a^1,a^2)=(A,B)
```

and never anything else.

Then the model has little evidence for what would happen under:

```math
(A,A),
\quad
(B,A),
\quad
(B,B).
```

Therefore we should distinguish two factors:

```math
\boxed{\text{interaction representation}}
```

and

```math
\boxed{\text{interaction coverage in the dataset}}.
```

This gives a useful supporting experiment.

Train with datasets containing different action diversity:

- low-diversity behaviour,
- mixed/random behaviour,
- high-diversity behaviour.

Then ask:

> When is explicit relational modelling enough to support counterfactual planning?

This can become a small but powerful analysis without changing the method.

## Scope

To keep the paper narrow, leave these out:

- foundation models,
- V-JEPA / DINO initialization,
- pixel observations,
- CTDE claims,
- decentralized MPC,
- learned communication,
- heterogeneous roles,
- agent-count generalization,
- uncertainty modelling,
- MCTS,
- policy distillation,
- large-scale MARL benchmarks.

These are possible follow-up papers.

The first paper only needs to establish:

```math
\boxed{
\text{simple multi-agent latent prediction}
+
\text{interaction modelling}
+
\text{MPC}
}
```

and understand why it works or fails.

## Expected Contributions

### 1. A Simple Interaction-Aware Latent World Model

A small relational predictor that explicitly models:

```math
(z_t^j,a_t^j)
\rightarrow
z_{t+1}^i.
```

The architecture should remain lightweight enough to train on a single GPU.

### 2. Counterfactual Planning Evaluation

Evaluate world models not only on logged prediction error, but also on:

```math
\text{counterfactual joint actions}
```

and

```math
\text{plan-ranking accuracy}.
```

### 3. An Empirical Link Between Model Structure and Control

Demonstrate whether:

```math
\text{interaction-aware modelling}
\rightarrow
\text{better plan ranking}
\rightarrow
\text{better MPC}.
```

The contribution is the **finding**, not architectural complexity.

## Proposed Paper Claim

If the experiments support the hypothesis:

> **A lightweight interaction-aware latent world model can improve multi-agent MPC by predicting the consequences of counterfactual joint actions more faithfully. The benefit is better captured by plan-ranking accuracy than by standard one-step prediction error.**

A slightly stronger version:

> **Explicit cross-agent state-action modelling improves counterfactual plan ranking and closed-loop predictive control in cooperative multi-agent environments, even when conventional prediction-error differences are small.**
